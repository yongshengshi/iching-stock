## 一、它做什么

页面分两个独立功能：

| 功能 | 说明 |
|---|---|
| **卜卦选股** | 点一下，全市场同坛起卦，选出卦象最好的三只（卦象互不相同）。每次点击**随机报数**，所以每次结果都不一样 |
| **个股起卦** | 输入代码或名称（支持 `gzmt` 这样的拼音首字母），得到该股完整判断：初卦 + 复卦 + 技术面 + 资讯面 + 买卖方案 |

点选股结果里的「诊断这只」，会自动切到个股起卦并回填代码。

## 二、核心设计

### 1. 报数起卦

梅花易数有「报数起卦」之法，本工具把它与股票代码、当下时空合参：

```
天时数 T = 年支序 + 农历月 + 农历日 + 时支序
上卦 = (代码数 + 报数 × 7) % 8     （余 0 取 8）
下卦 = (代码后三位数字和 + T + 报数 × 3) % 8
动爻 = (代码数 + T + 报数 × 5) % 6 （余 0 取 6）
```

**为什么三个乘数不同（7 / 3 / 5）**：如果三处都加同一个报数，等于把全市场的卦象整体平移一格，卦名一个都不会变，只是换了股票。用互质的乘数才能让报数真正改变卦象组合。

**为什么选股用「报数定位」**：卦气分只由「卦 + 动爻」决定，全市场最高分永远是那三四卦。若直接取 top3，每次都是同样三卦、只是股票不同。因此改为：先在**吉卦榜前 120 名**（本时辰最低 81 分）里用 `报数 % 120` 定位起点，从起点往后取三只卦象互不相同的——既保证都在吉卦段，又做到每次不同。

### 2. 双卜：初卦问股，复卦再验

- **初卦**：以报数 N₁ 起卦，定候选与基础分
- **复卦**：对选中的那只**再报一数 N₂**，另起一卦
- 两卦一吉一弱 → 判「两次矛盾，不投票」；同向则互相印证

注意：当 `N₂ − N₁` 是 24 的倍数时，三要素会同时归零、两次卦象完全相同，代码里已规避。

### 3. 三面合参：四票制

| 面 | +1 | 0 | −1 |
|---|---|---|---|
| **初卦** | 卦气 ≥ 66 | 52–65 | < 52（卦名不吉再扣一票） |
| **复占** | 复卦 ≥ 66 | 52–65 | < 52；与初卦一吉一弱 → 不投票 |
| **技术面** | 第 3–10 档 | 第 2 档 | 第 1 档（最差 10%） |
| **资讯面** | 有增持/回购/中标/预增… | 全是中性公告 | 有减持/立案/亏损/问询/风险提示… |

合计 **≥2 可入场 ｜ 1 轻仓试 ｜ 0 观望 ｜ ≤−1 回避**

技术面因子 = 低波（60 日日波动取负）+ 反转（20 日涨幅取负）+ 缩量（5 日均量/60 日均量取负），经 MAD 去极值、按 20 日均成交额五分位做**规模中性化**后等权合成，再分十档。

### 4. 点位：以该股日均波动为标尺

早期版本用固定百分比算点位，结果低波动股给太深、高波动股给太浅，几乎都成交不了。现在改为 ATR 基准：

```
ATR ≈ 现价 × 60日日均波动率

买一 = 现价 − ATR × (0.25 + 0.25×(1−k)) × 爻性系数     卦气越弱，等越深
买二 = 现价 − ATR × (0.75 + 0.55×(1−k)) × 爻性系数
止损 = 买二 − ATR × (0.60 + 0.30×(1−k))
目标一 = 现价 + ATR × (1.2 + 1.3k) × 趋势系数 × 天时系数
```

其中 `k = 卦气/100`；爻性系数 阳动 0.85 / 阴动 1.10；变卦趋凶 ×0.75；天时系数 `0.85 + 0.3×(天时/100)`；最后按**次日涨停价封顶**并做 0.01 元最小变动价位校正。

结论是买入价随个股自动缩放：日均波动 1% 的银行股买一贴在 −0.4%，波动 4.8% 的题材股则放到 −2%。

**卖出方案**（结论为观望/回避时切换）：弱股（体卦受克或卦气 < 52）给早盘 09:30–10:30 反弹减仓，其余按体旺时辰；减仓价 = 现价 + 0.35/0.75 × ATR，破位价 = 现价 − 0.9 × ATR。

## 三、回测结论（重要，请先读）

用腾讯/新浪日 K 数据，主板 3051 只 × 30 个交易日（2026-09-02 → 2026-10-21，91,240 个股票日）做严格 T+1 回测：

| 指标 | 结果 |
|---|---|
| 胜率 | **44.0%** |
| 平均单笔 | **−0.05%**（已扣 0.1% 成本） |
| 与「开盘买、收盘卖」基准相比 | 超额 **+0.01 个百分点/笔** |
| 评分 vs 次日涨幅 Spearman ρ | **0.0069** |

因子层面（303 个交易日横截面 IC，预测未来 5 日）：

| 因子 | IC | t 值 | IC>0 占比 |
|---|---|---|---|
| 缩量 | 0.0378 | 6.7 | 63.6% |
| 低波 | 0.0700 | 5.3 | 63.2% |
| 超跌 | 0.0416 | 4.6 | 61.1% |
| 20 日动量 | −0.0524 | −5.8 | 37.5%（A 股动量反向） |
| **玄学评分** | **0.0007** | **0.4** | **50.0%** |

**结论**：起卦评分与涨跌无关，这是**数学必然**——卦象只由（代码、日期、时辰、报数）决定，与价格、成交量、基本面完全独立。因此出场参数怎么调，都只能改变盈亏分布的形状，不能把期望变正：

| 出场配置 | 胜率 | 每笔期望（含跳空滑点） |
|---|---|---|
| 目标 0.5% / 止损 5% / 持 5 日 | 70.8% | **−1.21%** |
| 目标 5% / 止损 0.5% / 持 1 日 | 26.9% | −0.63% |

**胜率是个旋钮，不是能力。** 提高胜率的代价是单次亏得更多。这个项目真正的价值不是预测，而是：把「买多少、买在哪、错了怎么办」变成有纪律、可复盘的规则。

## 五、本地运行

无需构建，直接双击 `卜卦选股.html` 即可。也可以起本地服务（部分浏览器对 `file://` 的跨域更严格）：

```bash
npm run serve        # 等价于 python -m http.server 8899，访问 http://127.0.0.1:8899/
npm test             # 引擎单元测试
npm run build        # 改完 _ref/ 里的模板后重新生成页面
```

重新生成行情快照（需要 `npm i` 安装 pinyin-pro）：

```bash
node _ref/build_full.js          # 抓全 A 股行情 → data.json
node _ref/build_factor_data.js   # 需要先有 _ref/kline800.json（见下）
```

## 六、数据来源与已知限制

- **行情**：腾讯 `qt.gtimg.cn`（主）→ 东方财富 `push2.eastmoney.com`（备，独立厂商）→ 腾讯备线 `web.ifzq.gtimg.cn` → `script` 标签兜底
- **公告**：东方财富 `np-anotice-stock.eastmoney.com`。注意该接口**会拒绝带外站 Referer 的请求**（返回 567），必须 `referrerPolicy: 'no-referrer'`
- **技术面**：本地日 K 计算的因子快照（截至 `factor_data.json` 里的日期），**不是实时**；价格是实时的，两者时点不一致时请以页面标注为准
- 覆盖范围：沪深主板 2999 只（创业板/科创板/北交所无交易权限，未纳入技术面）
- 起卦评分**无预测力**；因子分段检验显示「优选高分行」不稳定，只有「排除最差档」相对可靠
